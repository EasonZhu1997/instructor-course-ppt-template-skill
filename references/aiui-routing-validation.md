# AIUI 自然触发实测

2026-11-05，macOS，DSH CLI 0.2.2-rc.1，实际响应模型均为 `deepseek-flash`。

## 测试方式

每条自然提问使用独立 DSH 会话与空工作目录，不在用户提示中点名技能，也不使用会强制加载课件技能的 `run_dsh.py`。测试只要求短提纲或技术回答，不生成文件。以成功的原生 `skill` 工具调用，以及真实参考文件内容的成功读取为证据；`read` 与能匹配源文件段落的 `cat`/`sed` 都计入，模型自述不计入。

## 升级前发现

旧安装只有 `course-ppt-template`，DSH 找不到位于 Codex 目录的 `aiui-dev`。三条 AIUI 教学自然提问没有一次使用真实 AIUI 技能或其文档，其中有的只加载了课件技能，有的直接回答。

这是依赖可用性和路由共同升级前的环境复现，**不是同一技能目录下仅修改 description 的纯 A/B**，也不是八条完整基线。实际执行的升级前自然请求只有 T01–T03。

## 升级后结果

| 案例 | 自然请求类型 | 观察到的原生技能 | AIUI 参考资料 | 结果 |
| --- | --- | --- | --- | --- |

| T02 | 小写 aiui 入门课提纲 | 课件技能、aiui-dev | framework | 通过 |

| T05 | 普通课程提纲 | 课件技能 | 无 AIUI 文档 | 未误触发 AIUI |

- AIUI 教学知识联动：**4/4**。
- 普通课程或明确排除 AIUI 时，无 AIUI 误触发：**3/3**。
- 纯开发问题只使用 AIUI 技能：**1/1**。
- 严格按原计划要求每条教学提纲都加载课件技能的完整功能矩阵：**6/8**，不是 8/8。T06、T08 直接回答了简短提纲。
- 进一步要求课件技能一定先于 AIUI 技能加载的严格顺序矩阵：**5/8**。T01 的两技能与真实文档都加载了，但顺序相反，不能抹去这一差别。

结果只覆盖上述八种实际措辞，不承诺所有表述都百分之百触发。独立审查未见四个 AIUI 课程答案有重大技术错或配色/设备验收越界；T07 回答额外给出的数组索引路径写法不在本轮所读 framework 文档中明确支持，记为未核准，不据此宣称全部技术细节已验证。

## 完整生成回归

另用升级后的执行器真实生成三页 AIUI 入门验证课件：日志记录 `course-ppt-template` 与 `aiui-dev` 两次成功原生加载，并实际读取 `framework.md` 和 `minimal-page.ink`，随后生成并独立验证 PPTX。此回归使用显式课件执行器，因此不计入上面的自然敏感度分数。
