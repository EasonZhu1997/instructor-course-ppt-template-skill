# Rokid AIUI 入门开发

请使用“讲师课程PPT模版Skill”制作 **总计 10 页**的中文入门教学课件。课程面向第一次接触 AIUI 项目的开发者，目标是看懂项目、理解最小 Page、学会数据绑定与基础交互，并能按检查清单验证预览结果。

完整课程名使用“Rokid AIUI 入门开发”。封面主标题显式写为三行“Rokid\nAIUI\n入门开发”，避免把英文长标题挤在一行。未提供讲师姓名，讲师槽可写“入门开发示例”，不要虚构讲师身份。10 页是本教学示例的编排选择。

## 内容依据与边界

基础代码概念依据本机 `aiui-dev` 技能的 `references/framework.md`、`references/events.md` 与 `assets/minimal-page.ink`。它们提供项目结构、默认导出、单文件页面、绑定、`setData` 与模板事件的实际契约。技能公开分发时不要求读者安装这些本机参考文件，以下摘录已给出本示例所需的最小事实。

- AIUI Studio 作为本课组织项目开发与预览工作的工作台。授课按“组织项目、编辑页面、观察预览、检查问题、迭代”讲解。不要虚构当前 Studio 的菜单、按钮、快捷键、固定界面位置或自动部署能力，操作入口以使用者当前版本为准。
- 项目可以包含 `app.json`、`app.js`、`pages/` 与 `assets/`。`app.json` 声明页面路由；`app.js` 用默认导出组织应用逻辑。初学示例先聚焦一个 Page，不扩展 Widget、Agent Worker、相机、网络或语音能力。
- 一个合法的示例页面路径为 `pages/index/index.ink`。对应的 `app.json` 路由声明为 `{"pages":["pages/index/index"]}`，路由不带 `.ink` 后缀。
- 单文件 `.ink` 页面包含 `<script def>`、`<script setup>`、`<page>` 和 `<style>`。`<script def>` 放 JSON 配置，`<script setup>` 放默认导出的逻辑对象，`<page>` 放页面模板，`<style>` 放页面样式。
- 同一个路由选择单文件 `.ink` 或多文件组织方式之一，不把两种形式混用。本课采用单文件 Page。
- 页面逻辑使用 `export default { ... }`，不要写成 `Page({...})` 或 `App({...})` 注册函数。
- 最小状态示例为 `data: { message: 'Hello AIUI' }`；模板用 `<text>{{message}}</text>` 显示文字。初始状态、绑定名称与模板输出应对应。
- 更新渲染状态使用 `this.setData({ message: '你好 AIUI' })`。不要教学生只修改 `this.data.message` 就期待界面自动更新，也不要虚构新的 SDK 调用。
- 模板事件可以写为 `bindtap="changeMessage"`，处理函数 `changeMessage()` 定义在默认导出的逻辑对象中，再通过 `this.setData(...)` 更新状态。不要替换成 DOM `onclick` 或套用浏览器事件机制。
- `bindtap` 是模板事件示例，不意味着每款眼镜都支持直接触摸屏幕。预览中的触发方式与目标设备的确认、返回、焦点事件应分别核对；本课不编造设备按键数量、映射或硬件参数。
- 预览检查应关注路由、页面显示、绑定更新和事件行为。预览结果与目标设备实际运行分开记录，不能将预览成功称为眼镜验收通过。
- 本次任务只输出课件和内容 JSON，**不真的新建、导入、发布或运行 AIUI 项目，也不声称完成设备实测**。课堂练习是面向学员的教学任务。

## 建议的 10 页内容

1. **封面**：Rokid AIUI 入门开发。短标题分三行，保留蓝紫课程模板。
2. **学习目标**：理解 Studio 开发流程、读懂项目与页面、观察最小应用预览、完成一次绑定与交互检查。侧栏提醒“先做一个 Page”“入口以当前版本为准”“预览与真机分别验证”。
3. **AIUI Studio 定位与流程**：项目编辑、预览观察、问题迭代三个环节。说明先围绕一个可观察的小目标推进，不编造 Studio 按钮名。
4. **项目结构与页面**：对照 `app.json` 与 `.ink` 页面：前者声明路由，后者包含页面配置、逻辑、模板和样式。使用短文案解释 `pages/index/index` 与 `pages/index/index.ink` 的关系；同一路由只采用一种组织方式。
5. **最小 Page**：解释四个单文件区块、`export default`、`data.message` 与 `{{message}}`。以显示“Hello AIUI”为最小可观察目标；样式沿用主题变量，不给根节点写死设备像素尺寸。
6. **数据绑定与状态更新**：对照“初始文字”与“状态更新”，说明模板读取 `data`，更新通过 `this.setData(patch)`，再观察预览结果。代码标识可用短片段，不为填充版面编造 API。
7. **基础交互**：`bindtap` 指向处理函数，处理函数更新状态，页面显示新文字。说明这是模板事件链，真实设备输入与焦点需要单独验证。
8. **调试检查**：先查 `app.json` 路由与文件，再查默认导出及区块结构，最后查绑定名、处理函数名和更新后的显示。给出具体检查顺序，避免使用不存在的 Studio 调试面板名称。
9. **课堂练习**：整理一个 Page 的文件与路由；将“Hello AIUI”改为自己的欢迎语并检查预览；加入一个模板事件更新文字并记录现象。练习时长未指定，时长槽可写“课堂练习”，不编造固定课时。
10. **验收与结课**：交付项目骨架、最小页面、绑定交互说明和预览记录。明确“源码结构正确、预览行为正常、目标设备通过”是不同检查项，后者需要后续实际验证。

## 视觉要求与 AIUI 屏幕配图

- 整套课件保留既定蓝紫模板、字体、字号、边界和装饰，不把整页或整套 PPT 改为绿色。
- 如插入 AIUI 视觉示意，仅 **AIUI 显示画面范围内** 使用黑底与单一绿色的文字、细线和焦点。绿色约束不扩散到课件标题、页脚或背景。
- 示意屏幕只呈现“Hello AIUI”“欢迎进入”或简单状态变化等最小页面内容。使用相对布局、留白与清晰层级，不标注未经本课核实的分辨率、视场角或设备参数。
- 黑色是透明显示的设计底层，不把不透明黑色遮挡现实环境宣称为设备能力。
- 若当前生成流程支持插入真实图片，使用已实际生成并确认存在的图片文件；不要把空框、提示词或“这里放图”当作已完成配图，也不要假称为 Studio 或眼镜实拍。

## 生成与验收

- 总计 10 页，所有选用页型完整填写非 auto 槽，遵守当前 profile 的字符、每行字符与行数预算。概念页正文和底部总结各为单行，对照页左右正文最多两行；文字过长时精简，保持模板字号与几何结构。
- 覆盖 Studio 定位与流程、项目结构和页面、最小应用与预览、数据绑定、事件交互、调试、练习与验收。
- 生成普通可编辑 PPTX，并保留对应 `content.json`。只运行课件引擎的 build、validate 与渲染检查，不运行 AIUI 项目。
- 最终检查全部 10 页的中文、英文代码标识、换行、边界和配图。注明配图是教学示意；结构验证和课件渲染不代表眼镜或 Studio 运行验收。
